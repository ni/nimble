The query builder combines the query editor with saved queries, Nigel assistance, and actions to apply or cancel changes. The host application supplies the fields and operators, current query, saved queries, and asynchronous save and delete handlers. The builder keeps track of drafts. Saving a query and applying it are separate actions.

The split button shows **Configure query** when no saved query is selected, or the selected saved query's name. Its primary button opens a popover with query conditions, Nigel assistance, and Apply, Cancel, and Done buttons. This view has no name field or save and delete actions. The dropdown button opens the saved-query menu. **Edit saved query** and **Create saved query** open a popover with a name field and save actions. Both views use the same draft.

Place the query builder directly in an application toolbar or a toolbar slot. It sizes to its split button and has no internal toolbar, surrounding border, or toolbar padding. The containing toolbar controls spacing and alignment. The query popover is at most 600px wide, stays within the viewport, and can open above the split button when space below is limited. Its contents scroll when necessary. Footer actions stay together and wrap below the secondary actions only when they no longer fit beside them.

## Configuring the example

Use `preset` to choose an empty, grouped, invalid, saved, or complex query. Set `query` to override the preset with a custom query document, and use `definition` to configure fields and operators.

The Controls panel also lets you change the saved queries, disabled state, and feature flags. Enable `persistence` to try the in-memory save and delete handlers. Enable `failFirstSave` to make the first save fail, then retry without losing the draft.

Enable `aiPreview` to show a sample generated query. Sending a Nigel prompt also shows this sample. The example does not call an AI service.

## Portable data contract

Set `definition`, `query`, and `savedQueries` as JavaScript properties, not HTML attributes. The definition specifies stable field IDs, JSON Pointer paths, JSON Schemas for values, and the values each operator accepts. A query is a versioned document that can contain nested groups. The editor keeps unfinished conditions and expressions in a `QueryEditorDraft` rather than exposing them as an executable query.

```ts
import {
    fvQueryBuilderTag,
    type QueryBuilderDefinition,
    type QueryBuilderSavedQuery,
    type QueryDocument
} from '@ni/ok-components/dist/esm/fv/query-builder';

declare function deleteSavedQuery(id: string): Promise<void>;
declare function applyToResults(query: QueryDocument, selectedId?: string): void;

const definition: QueryBuilderDefinition = {
    version: 1,
    fields: [{
        id: 'status',
        path: '/status',
        label: 'Status',
        valueSchema: {
            oneOf: [
                { const: 'failed', title: 'Failed' },
                { const: 'passed', title: 'Passed' }
            ]
        },
        operatorIds: ['is'],
        editor: { kind: 'select' }
    }],
    operators: [{
        id: 'is',
        label: 'Is',
        operand: { kind: 'field-value' }
    }]
};

const query: QueryDocument = {
    version: 1,
    root: {
        kind: 'predicate',
        fieldId: 'status',
        operatorId: 'is',
        value: 'failed'
    }
};

const savedQueries: readonly QueryBuilderSavedQuery[] = [{
    id: 'failed',
    name: 'Failed tests',
    document: query
}];

const builder = document.createElement(fvQueryBuilderTag);
builder.definition = definition;
builder.query = query;
builder.savedQueries = savedQueries;
builder.saveHandler = async request => ({
    id: request.id ?? 'new-query',
    name: request.name,
    document: request.document
});
builder.deleteHandler = async id => {
    await deleteSavedQuery(id);
};
builder.addEventListener('query-apply', event => {
    const detail = (event as CustomEvent<{
        readonly query: QueryDocument;
        readonly selectedId?: string;
    }>).detail;
    applyToResults(detail.query, detail.selectedId);
});
```

Provide `saveHandler` and `deleteHandler` to enable save and delete actions. A save request creates or updates a saved query and contains a copy of its name and query document. The handler returns the saved record. If the promise rejects, the builder keeps the draft and shows an error so the user can retry. The host application handles authorization, IDs, permanent storage, and translation to backend query formats.

When the selected saved query has unsaved changes, **Update saved query** saves those changes under the same ID. **Create saved query** saves a copy with a new ID.

All four feature flags default to `true`. `showNigelPrompt` controls Nigel assistance and the generated-query preview. `allowSavedQueryCreation` controls creating saved queries, including copies of existing saved queries. `allowSavedQueryEditing` controls editing and updating existing saved queries; users can still change query conditions and, if creation is enabled, save a new query. `allowSavedQueryDeletion` controls the delete action and its confirmation. Disabling creation does not prevent applying query conditions or updating existing saved queries.

```ts
builder.showNigelPrompt = false;
builder.allowSavedQueryCreation = false;
builder.allowSavedQueryEditing = false;
builder.allowSavedQueryDeletion = false;
```

Switching queries keeps the draft for the query you leave and automatically applies the selected query's draft if it is valid, including when returning to **Current query**. An incomplete or invalid draft remains available for editing without changing the applied query. **Save** saves a query without applying it or closing the popover. **Apply** validates the draft and emits `query-apply` with the query document and selected saved-query ID (`undefined` for Current query). It also leaves the popover open.

**Done** closes the popover without saving, applying, or discarding drafts. It is not shown when editing a saved query. **Cancel** restores the last applied query document and selection. It does not undo completed saves or discard drafts for other saved queries.

The builder does not execute queries. An empty query document is valid and means no filtering. Users cannot apply incomplete or invalid drafts. The `query-change` event includes a copy of the draft, a validated query document or `null`, the condition count (`ruleCount`), and validity. Use `labels` to localize the builder and editor.

## Nigel assistance

**Ask Nigel** is a ghost button in the query editor heading, 8px above the editor outline. Clicking it shows a Spright chat input below the button. Sending a prompt emits `query-ai-request` with the trimmed prompt text and a copy of the current draft. The host application can then set `aiQueryPreview` to a generated query document for review in the same popover. The builder does not call an AI service or save generated queries.

## Visual hierarchy

The **Queries** split button and **Add filter** button use ghost appearance. In the saved-query view, the **Name** field and **Ask Nigel** button share a row. The name field and secondary actions use outline appearance, and the chat input uses Spright styling. **Apply** is the only accent-filled action. Clear and delete actions are separate from Cancel, Done, Save, and Apply.

The query editor controls the appearance of condition chips and AND/OR controls. The popover has aligned content insets, 16px gaps between sections, and 8px gaps between actions. The query editor has an 8px gap above it and before **Add filter**. **Query conditions** uses the control-label font tokens; **Name** uses the text field's native label.

## Accessibility

Both buttons in the Queries split button support keyboard interaction. They are in a named group rather than a nested toolbar. The dropdown menu has an accessible name and identifies the selected query. The query popover is a nonmodal dialog anchored to the split button. The saved-query view has a visible label for the name field, and **Ask Nigel** exposes whether the prompt is expanded in either view.

Unsaved-change indicators include accessible text. The builder announces save and delete errors. The primary button focuses the query input; **Edit saved query** and **Create saved query** focus the name field. Dismissing the popover returns focus to the primary button. Within the query editor, condition popovers and select dropdowns handle Escape separately from the query popover.
