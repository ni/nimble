An independently usable inline query editor for field conditions, AND/OR operators, and parenthesized filter groups. This Storybook surface is used to refine its visual and keyboard interactions before the editor is composed into the query builder.

Use the **Controls** panel to configure the editor label, disabled state, default field, layout, field/operator definition, and query document.

## Formatted layout

Set `layout` to `"formatted"` to put each condition on its own aligned row and indent grouped conditions. Nested groups continue indenting through four levels (`MAX_QUERY_GROUP_DEPTH`). Switching `layout` changes presentation only; the query and draft are preserved. The default `"inline"` layout is unchanged.

## Data and events

`definition`, `query`, and `draft` are property-only values. The definition declares stable field IDs and JSON Pointer paths, JSON Schemas for values, allowed operators, and optional editor configuration. The query is a versioned recursive document with a maximum nested-group depth of `MAX_QUERY_GROUP_DEPTH`; the draft is a versioned token snapshot that can also preserve unfinished text inputs. The portable contract is the editor's only API; it has no adapter for the removed grouped-query shape.

```ts
import {
    fvQueryEditorTag,
    type QueryBuilderDefinition,
    type QueryEditorEventDetail,
    type QueryDocument
} from '@ni/ok-components/dist/esm/fv/query-editor';

const definition = {
    version: 1,
    fields: [{
        id: 'status',
        path: '/status',
        label: 'Status',
        valueSchema: {
            oneOf: [
                { const: 'failed', title: 'Failed' },
                { const: 'passed', title: 'Passed' }
            ]
        },
        operatorIds: ['is']
    }],
    operators: [{
        id: 'is',
        label: 'is',
        operand: { kind: 'field-value' }
    }]
} satisfies QueryBuilderDefinition;

const editor = document.createElement(fvQueryEditorTag);
editor.definition = definition;
editor.query = { version: 1, root: null } satisfies QueryDocument;
editor.layout = 'formatted';
editor.addEventListener('query-change', event => {
    const detail = (event as CustomEvent<QueryEditorEventDetail>).detail;
    workingDraft = detail.draft;
    if (detail.query !== null) {
        workingQuery = detail.query;
    }
});
```

`query-change` fires for user edits with a detached snapshot. `query` is a validated document when the edit is complete and `null` while the draft is incomplete or invalid; `draft` remains the source of truth and can be reassigned to restore an unfinished expression. Draft tokens retain numeric/date input text in `rawInputs`, so invalid intermediate keystrokes are not lost. Programmatic property changes do not emit `query-change`.

The `issues` property and `validity-change` event report definition, query, and draft errors. `configuration-error` reports an invalid definition. Dynamic options are supplied through `optionResolver`; each select or combobox `optionsSource` includes a host-defined `sourceId`, optional dependencies, search support, and page size. The resolver receives those dependent values and an `AbortSignal`; `options-state-change` reports loading, ready, blocked, and error states, while `options-error` reports failures.

For dynamic values, keep the source lookup in the host and pass only its identifier and dependencies in the definition:

```ts
import type { QueryOptionPage, QueryOptionRequest } from '@ni/ok-components/dist/esm/fv/query-editor';

declare function searchWorkspaces(
    request: QueryOptionRequest,
    signal: AbortSignal
): Promise<QueryOptionPage>;

editor.definition = {
    version: 1,
    fields: [{
        id: 'workspace',
        path: '/workspace',
        label: 'Workspace',
        valueSchema: { type: 'string' },
        operatorIds: ['is'],
        editor: {
            kind: 'combobox',
            optionsSource: {
                sourceId: 'workspaces',
                dependsOn: ['tenantId'],
                searchable: true,
                pageSize: 25
            }
        }
    }],
    operators: [{ id: 'is', label: 'is', operand: { kind: 'field-value' } }]
};
editor.optionContext = { tenantId: 'tenant-1' };
editor.optionResolver = {
    resolve: (request, signal) => searchWorkspaces(request, signal)
};
```

`searchWorkspaces` is a host function that returns a `QueryOptionPage`. The resolver receives `sourceId`, field/operator IDs, the required dependent values, optional search text and cursor, and an abort signal. Changing context or search cancels the previous request; resolver failures can be retried without invalidating an otherwise valid document.

The editor does not apply queries or provide saved-query, AI, or footer workflows. It is not a drop-in Stratus query-builder replacement: applications must map field/operator and query shapes themselves, including preserving datetime semantics. The editor does not generate Stratus filter objects or LINQ.

## Accessibility

Conditions are keyboard-activatable expandable chips. The inline query control supports token navigation and deletion, field and logic autocomplete, and visible validation for incomplete grouping and conditions. The editor popover returns focus to its chip when dismissed with Done or Escape.
