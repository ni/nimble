| Part | Implementation |
| --- | --- |
| Container | Native `button` in the shadow DOM, exposed as the `control` part. Owns the boundary, fill, and interaction states. |
| Icon | Optional `start` and `end` slots. The diagram shows a start icon. |
| Label | Default slot inside the `content` part. With `content-hidden`, the label is visually hidden but remains available to assistive technology. |

## Tokens & states

Button and Anchor Button share the
[button pattern styles](https://github.com/ni/nimble/blob/main/packages/nimble-components/src/patterns/button/styles.ts).
Keep shared visual behavior there rather than duplicating it in each component.

| Concern | Implementation |
| --- | --- |
| Size & spacing | `controlHeight` sets the height; `standardPadding` sets horizontal padding. Icon-to-label spacing is 4px. |
| Typography | `buttonLabelFont` and `buttonLabelFontColor`; disabled text uses `buttonLabelDisabledFontColor`. |
| Appearance variants | Primary uses `buttonFillPrimaryColor` and `buttonPrimaryFontColor`. Accent uses `buttonFillAccentColor`, `buttonAccentBlockFontColor`, `buttonBorderAccentOutlineColor`, and `buttonAccentOutlineFontColor`. |
| Interaction | Hover and keyboard focus use `borderHoverColor`; active uses `fillSelectedColor`. Disabled buttons suppress interactive styling. |

Review the [theme matrix](?path=/story/tests-button--theme-matrix) and
[interaction matrix](?path=/story/tests-button--interactions-theme-matrix)
when changing styles. These cover more states than the examples on the Usage page.

## Implementation constraints

The [Button template](https://github.com/ni/nimble/blob/main/packages/nimble-components/src/button/template.ts)
uses a native button for keyboard and form behavior. Preserve that behavior and
accessible naming when changing its structure.

Icon-only buttons retain their label, use a square container, and hide the end
icon. Keep these behaviors aligned with the consumer guidance on the Usage page.
